### 1.2 Historical execution patterns (from Slurm scripts)

The surviving `test_charts/slurm/trillium_pipeline.slurm` encodes the historical pattern:

1. **Environment via modules** — `StdEnv/2023`, `gcc/12.3`, `cuda/12.6`, `python/3.11`, `scipy-stack`, `hdf5`, `ffmpeg`. Hard blocker for portability.
2. **Repo-root resolution via `SLURM_SUBMIT_DIR`** — brittle path probing (`test_charts/charts_sim.py` existence checks).
3. **Scratch routing** — explicit avoidance of `/dev/shm` tmpfs after OOM incidents (commit `28439aef8`); prefers `$SCRATCH` / `$SLURM_TMPDIR`.
4. **In-job build** — `cmake -DUSE_CUDA=ON -DCMAKE_CUDA_ARCHITECTURES="90;80" -DUSE_NUMA=ON`, `make -j kotekan` if binary missing.
5. **Single-shot pipeline** — `charts_sim.py pipeline --preset {1min,5min} --profile {day,night}` runs generation → correlation → tracking → validation → visualization monolithically.

Lessons from `kotekan_charts` history: Slurm OOM from tmpfs scratch, `--mem` flag incompatibility with Trillium, sequential-window sequencing to bound disk usage. These are cluster scars the new framework must not re-inherit.

### 1.3 Structural gaps & bottlenecks identified

| # | Finding | Evidence | Impact |
| :--- | :--- | :--- | :--- |
| G1 | **Monolithic pipeline coupling.** `charts_sim.py pipeline` always runs all 5 steps; baseband writing cannot be consumed without a full Kotekan run, and Kotekan stages cannot be exercised without regeneration. | `charts_sim.py::run_pipeline` Steps 1–5 sequential | Violates modularity goal; slows iteration on X-engine stages. |
| G2 | **Dual simulation paths with drift risk.** Physics exists twice: Python generator (`sim/generator.py`, `sim/noise_model.py`) and C++ `chartsFEngineSim` stage (hardcoded target catalog, `C_LIGHT`, `K_DM` constants re-declared in an anonymous namespace). | `lib/stages/chartsFEngineSim.cpp` lines 24–50 | Constants parity violation per workspace `AGENTS.md` §2.3; Julia-reference parity untestable across two generators. |
| G3 | **Trillium assumptions linger.** Slurm script is the only documented production path; presets reference "RTX 4090/5090 and Trillium" but there is no machine-profile abstraction (module loading, scratch policy, GPU arch are hardcoded). | `trillium_pipeline.slurm`, `sim/presets.py` docstring | Portability goal unmet. |
| G4 | **No Julia cross-validation harness.** Reference windows (`test_charts/data/reference_windows/ref_{32,64}ant`) are self-generated by the Python simulator — circular validation. No automated comparison against `RadioTelescopeFEngine.jl` output. | `sim/reference.py`, `test_charts/tests/` | Accuracy-vs-Julia goal unmeasured. |
| G5 | **Heavy test/validation posture.** Legacy C++ suites (1.2k-line beam tracker suite, chaos engineering) were deleted wholesale; current `test_charts/tests/` has only 3 files. No lightweight statistical validation tier. | diff stat: −24,281 lines | Confidence gap on low-resource machines. |
| G6 | **Scratch/output lifecycle unmanaged.** `scratch_charts_sim/` accumulates at repo root; no retention/cleanup policy abstraction. | `scratch_charts_sim/charts_sim_{32,64,256}ant` | Disk exhaustion on small machines. |
| G7 | **Config schema implicit.** `SimulationConfig` dataclass is the de-facto schema; no versioned YAML schema, no validation, no machine-profile overlay. | `sim/presets.py` | Fragile cross-machine reproducibility. |

### 1.4 Optimization opportunities

- **O1:** Chunked multiprocessing generation already exists (`sim/generator.py`); extend with a frame-streaming writer so baseband `.bin` frames are produced incrementally and can be memory-mapped by `rawFileRead` without full materialization.
- **O2:** Reuse the reference-window library as a content-addressed cache (checksums already in `window_manifest.json`) so `correlate`/`track`/`benchmark` skip regeneration.
- **O3:** Port the high-value legacy C++ suites (phase interpolation, beam tracker) as *parameterized small-grid* tests (8–16 antennas, few channels) instead of the deleted 64–256-antenna monoliths.
- **O4:** GPU arch detection (`CMAKE_CUDA_ARCHITECTURES`) should be auto-detected (`native`) with override, not pinned to `"90;80"`.

## 2. Specification & Requirements Document

### 2.1 Architecture overview

```
┌────────────────────────────────────────────────────────────────────┐
│                     charts_sim.py (CLI orchestrator)               │
│   generate │ write-baseband │ correlate │ track │ inspect │        │
│   visualize │ benchmark │ reference │ validate-julia               │
└──────┬─────────────────────────────────────────────────────────────┘
       │ SimulationConfig (versioned YAML schema + machine profile)
       ▼
┌────────────────── sim/ package (pure Python, no Kotekan deps) ─────┐
│  constants.py   — physical/instrument constants (parity-checked    │
│                   against charts-constants)                        │
│  astro.py       — LST, RA/Dec→(l,m,n), source catalog, visibility  │
│  noise_model.py — analog chain T_sys (Sun, ground spill, rx)       │
│  generator.py   — baseband voltage synthesis + event scheduler     │
│  writer.py (NEW)— frame serialization & file writing ONLY          │
│  reference.py   — reference window library + manifests + checksums │
│  pipeline.py    — Kotekan YAML emission & process orchestration    │
│  inspector.py   — Hermitian/SNR/dynamic-range checks               │
│  visualizer.py  — plots (optional, matplotlib-gated)               │
│  benchmark.py   — GPU tracker perf/VRAM/cadence                    │
│  julia_ref.py (NEW) — RadioTelescopeFEngine.jl bridge & comparator │
└────────────────────────────────────────────────────────────────────┘
       │ baseband frames (.bin int4x2) + HDF5 metadata + events.json
       ▼
┌────────────────── Kotekan pipeline (C++/CUDA) ─────────────────────┐
│  rawFileRead → [cudaCorrelatorAstron | cudaDirectBeamTracker |     │
│  antenna masking | BiSLC] → rawFileWrite / inspection stages       │
│  (chartsFEngineSim retained as in-pipeline generator alternative)  │
└────────────────────────────────────────────────────────────────────┘
```

### 2.2 Modularity requirement: baseband generation/writing isolation

**R2.1 — Writer as a separate component.** Extract frame serialization from `generator.py` into `sim/writer.py` with a minimal interface:

```python
class BasebandWriter(Protocol):
    def write_frame(self, frame_id: int, voltages: np.ndarray) -> None: ...  # int4x2 packed
    def write_metadata(self, meta: WindowMetadata) -> None: ...               # HDF5 sidecar
    def finalize(self) -> WindowManifest: ...                                 # checksums, frame count
```

Two implementations: `RawBinWriter` (Kotekan `rawFileWrite`-compatible sequential `.bin`) and `HDF5Writer` (analysis-friendly). Generation code must depend only on the `BasebandWriter` protocol — never on file layout.

**R2.2 — Independent CLI commands.** Every stage boundary is a command:
- `charts_sim.py generate` → voltages in memory → writer → frames on disk. **No Kotekan invocation.**
- `charts_sim.py correlate|track` → consume an existing window directory (reference library or scratch). **No regeneration** unless `--regenerate`.
- `charts_sim.py reference save|list|info` → promote a scratch window into the checksummed library.

**R2.3 — Data contract between generator and X-engine stages.** The on-disk window directory is the *only* interface:

```
<window_dir>/
├── <name>_0000000.bin … .bin        # int4x2 frames, fiducial 5D order (t_pkt, dish, pol, freq, t_samp)
├── <name>_meta.h5                   # antenna positions, freq map, LST0, event catalog, analog params
├── events.json                      # transient/RFI schedule (ground truth for validation)
├── sim_config.yaml                  # resolved SimulationConfig (schema-versioned)
└── window_manifest.json             # SHA-256 per frame, frame count, git SHA of sim package
```

Kotekan YAML configs (`create_correlator_yaml`, `create_beam_tracker_yaml`) must reference this directory by path only; no other coupling.

### 2.3 Interface boundaries

| Boundary | Producer → Consumer | Contract |
| :--- | :--- | :--- |
| B1: Physics → Serialization | `generator.py` → `writer.py` | `np.ndarray` complex frames + `WindowMetadata` dataclass; int4x2 packing inside writer only |
| B2: Sim → Kotekan | window dir → `rawFileRead` | `.bin` frames + Kotekan YAML emitted by `pipeline.py`; frame geometry (`samples_per_frame`, `num_elements`, `num_local_freq`) mirrored in both manifest and YAML, cross-validated before launch |
| B3: Kotekan → Validation | dump dirs → `inspector.py` | correlator/tracker dump layouts as defined by `cudaCorrelatorAstron` / `cudaDirectBeamTracker` output stages |
| B4: Sim ↔ Julia reference | `julia_ref.py` ↔ `RadioTelescopeFEngine.jl` | shared HDF5 exchange format: complex64 voltages, float64 phases, common antenna/freq/LST grid (see §2.5) |
| B5: Config → everything | `sim_config.yaml` → all modules | JSON-Schema-validated, `schema_version` field mandatory |

### 2.4 Configuration schema

```yaml
schema_version: 1
preset: quick                # quick | 1min | 5min | custom
profile: day                 # day | night | both
machine: local               # local | trillium | <custom profile name>
window:
  name: charts_sim
  duration_s: 5.0
  start_time_utc: null       # ISO-8601 or null → utc_hour
array:
  antennas: 64
  num_freq: 336
  samples_per_frame: 1536
  frequency_start_mhz: <from constants>
events:
  num_events: 1
  persistent_rfi_channels: [94, 133, 147]
  seed: 42                   # mandatory for reproducibility
pipeline:
  max_beams: 4
  buffer_depth: 2
  kotekan_bin: null          # null → auto-detect build/kotekan/kotekan
machine_profiles:            # overlay selected by `machine:`
  local:    { workers: auto, scratch_dir: ./scratch_charts_sim, gpu_arch: native }
  trillium: { workers: $SLURM_CPUS_PER_TASK, scratch_dir: $SCRATCH/…, gpu_arch: "90;80",
              modules: [StdEnv/2023, gcc/12.3, cuda/12.6, python/3.11] }
```

Requirements:
- **R2.4a** No absolute paths in any committed config or script; all paths derive from repo root + `scratch_dir`.
- **R2.4b** Machine profiles are data (YAML), not code; adding a cluster = adding a profile block.
- **R2.4c** Slurm launcher becomes a thin wrapper: `sbatch` → loads profile modules → `charts_sim.py pipeline --machine trillium`. No path probing, no in-job cmake unless `--build` passed.

### 2.5 Numerical & physical fidelity targets (parity with Julia reference)

Grounded in workspace `AGENTS.md` §2 (coordinate/delay conventions) and §3 (equivalence testing). The Julia simulator (`RadioTelescopeFEngine.jl`) is the accuracy oracle; comparisons run through `sim/julia_ref.py` on a common reduced grid (default: 8 antennas × 8 freq channels × 1024 samples).

| ID | Quantity | Target | Method |
| :--- | :--- | :--- | :--- |
| F1 | Geometric delay $\tau_{ij} = \vec{b}_{ij}\cdot\hat{s}/c$ | abs err < 1 ps (≪ FPGA 2.56 µs resolution) | identical ENU antenna table & LST fed to both simulators |
| F2 | Fringe-stopping phase $\phi_{ij} = 2\pi f \tau_{ij}$ | abs err < 10⁻⁴ rad over full window | per-frame phase dump comparison (float64 exchange) |
| F3 | Beam steering pointing | < 10⁻⁴ rad (per AGENTS.md §3) | formed-beam peak vs. injected $(l_0, m_0)$ |
| F4 | Complex voltage cross-correlation (pre-quantization) | coherence > 0.999 per baseline/channel | float64 Julia output vs. Python float path |
| F5 | 4-bit quantization SNR loss | within theoretical bound < 0.5 dB of ideal quantizer | compare quantized SNR against analytic $ \text{SNR}_q $ curve |
| F6 | int4x2 byte packing | bit-exact: `Byte = (Re & 0x0F) | ((Im & 0x0F) << 4)` | byte-level fixture vectors |
| F7 | Noise model $T_\text{sys}$ | day/night Sun elevation sign, ground spillover 2% × 290 K = 5.8 K, $T_\text{rx}$ ∈ (20, 25) K | unit tests (already partially present) |
| F8 | Dispersion sweep (FRB) | $\Delta t = K_\text{DM}\,\text{DM}\,(f_\text{lo}^{-2} - f_\text{hi}^{-2})$, $K_\text{DM} = 4148.808$ s·MHz²/(pc cm⁻³) | arrival-time fit vs. analytic, < 1 sample |
| F9 | Constants parity | zero hardcoded constants in C++/Python sim paths; `chartsFEngineSim.cpp` must source from generated constants header | parity test + lint grep |

**Fidelity-loss budget:** the only sanctioned fidelity reductions vs. Julia are (a) reduced grid size for local tests, (b) decimated frame-selection schedule for long windows. Both must be *sampling* reductions, never model reductions — physics code paths are identical at any grid size.

### 2.6 Hardware considerations

- **R2.6a — Local tier:** full test suite ≤ 4 GB RAM, ≤ 5 min, GPU optional (CPU-only tests must pass; GPU tests auto-skip without CUDA).
- **R2.6b — Production tier:** same code paths scale via `machine` profile; buffer depth and worker counts are profile parameters, not code edits.
- **R2.6c — Scratch lifecycle:** every run gets a unique scratch subdir; `charts_sim.py` exposes `--clean-scratch` and auto-prunes runs older than N days (default 7) on the local profile.
- **R2.6d — GPU architecture:** default `native` detection; profile override for clusters.

Tiered so that T1+T2 run locally in minutes with no GPU and no Kotekan binary; T3 runs where Kotekan is built; T4 runs where Julia is available.

### Test infrastructure requirements

- **T-Infra1:** all tiers via `pytest test_charts/tests -m "tier1|tier2|tier3|tier4"` markers; default local run = tier1+tier2.
- **T-Infra2:** reference windows for tests live in `test_charts/data/reference_windows/` at 8-ant resolution (add `ref_8ant`, ~MB-scale); 32/64-ant windows reserved for production validation.
- **T-Infra3:** statistical tests use fixed seeds and distributional assertions (χ², coherence), never exact float equality across RNG implementations.
- **T-Infra4:** CI matrix: tier1+tier2 on every push (CPU runner); tier3 on GPU runner; tier4 nightly.

## 4. Implementation sequencing (for the coding agent)

1. **S1 — Writer extraction (R2.1, R2.2):** create `sim/writer.py` with `BasebandWriter` protocol, `RawBinWriter`, `HDF5Writer`; refactor `generator.py` to depend on the protocol; add `--writer` flag and standalone `write-baseband` command. Tests: `test_writer.py`, `test_writer_independence.py`.
2. **S2 — Config schema & machine profiles (G3, G7, R2.4):** versioned YAML schema, `machine_profiles` overlay, rewrite `trillium_pipeline.slurm` as thin wrapper, auto GPU arch. Test: `test_config_schema.py`.
3. **S3 — Julia bridge (G4, §2.5):** `sim/julia_ref.py` (HDF5 exchange + `julia --project` subprocess runner), tier-4 tests, `validate-julia` CLI command.
4. **S4 — Constants parity (G2, F9):** generate a C++ constants header from `charts-constants` (mirror of `beamform_project/scripts/sync_constants.py`), refactor `chartsFEngineSim.cpp` to consume it; extend parity test.
5. **S5 — Test tiering & legacy ports (G5, O3):** pytest markers, `ref_8ant` window, port phase-interpolation/tracker C++ suites as small-grid ctest targets.
6. **S6 — Scratch lifecycle (G6, R2.6c):** unique run dirs, `--clean-scratch`, retention pruning.

Each step lands independently on `feat/charts-simulation-framework` with its tier-1/2 tests green before the next begins.
